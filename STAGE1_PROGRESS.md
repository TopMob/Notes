# Этап 1: первый пакет защиты локальных данных

Дата: 9 октября 2026. Первый пакет подготовлен в ветке `codex/stage1-local-safety` для отправки в `main` и автоматического выпуска Vercel по прямой просьбе пользователя. Копия Firefox на ноутбуке пока отсутствует. Инструменты проверки не изменяли рабочие локальные и облачные данные. Изменений схемы и нового облачного протокола в пакете нет.

## Реализовано

- Инициализация больше не очищает базу по наличию `nb-college`. Начальные записи создаются только при отсутствии данных во всех проверяемых хранилищах, включая assets. Убрано автоматическое назначение произвольного раздела страницам без связи.
- Неудачный локальный diff возвращается в очередь. Новые изменения и удаления имеют приоритет над старой неудачной операцией; параллельные записи одной страницы сериализованы.
- В заголовке появился отдельный статус локального сохранения и кнопка повторной записи. Успешная старая запись не обозначает новые ожидающие правки как сохранённые.
- Переключение страницы ждёт записи. Ошибка записи сохраняет текущий холст. Повторная загрузка той же страницы также сначала сохраняет правки; устаревшие ответы загрузки и ответы после новых правок отвергаются.
- Debounce остаётся 400 мс, максимальное ожидание начала записи при непрерывном вводе — 2 секунды. При скрытии страницы предпринимается сохранение; штатное закрытие с несохранёнными изменениями запрашивает стандартное предупреждение браузера. Эти обработчики не гарантируют запись при аварийном завершении браузера или ОС.
- Ошибка записи изображения отвергает вставку и освобождает временный ObjectURL. Все четыре пути вставки обрабатывают отказ.
- JSON-экспорт сначала сохраняет редактор и читает шесть таблиц одной readonly-транзакцией. Интерфейс явно сообщает, что бинарные изображения в этот старый формат не входят.
- Старый JSON-импорт проверяет версию, обязательные массивы, основные поля объектов, уникальность ID и связи до записи. Неполный файл больше не трактуется как пустая база.

## Проверено

`npm test`: 62 теста прошли, включая 13 новых проверок настоящих модулей приложения с заменой границ ввода-вывода. Проверены ошибки записи, повтор, конкурирующие правки/удаления, сериализация, непрерывный ввод, отсутствие очистки legacy-данных, отклонение неполного импорта, отказ записи изображения и поздние ответы загрузки.

`npm run build`: TypeScript и production-сборка прошли. Сохраняются предупреждения Vite о большом основном бандле и смешанном статическом/динамическом импорте storage.

`scripts/tests/local-safety-browser.mjs`: в новом изолированном Chromium проверен настоящий компонент статуса и store: сохранено → есть правки → ошибка → кнопка повтора → сохранено. Граница IndexedDB заменена управляемым отказом; исходный diff после повтора сохранён. Опубликованный сайт и профиль пользователя не открывались. Для запуска требуются установленный Playwright (`NOTES_PLAYWRIGHT_MODULE`) и его Chromium (`PLAYWRIGHT_BROWSERS_PATH`). Это не проверка Firefox пользователя.

Откат этого пакета: revert коммита исправлений в `main`, затем обычный повторный деплой. Пакет не меняет схему IndexedDB или формат облачных записей. Проверенный Git bundle исходного состояния и восстановленный Turso-снимок этапа 0 хранятся отдельно от репозитория.

## Осталось до завершения этапа 1

- Полный формат бэкапа с бинарными assets, manifest и контрольными суммами; совместимость со старым JSON.
- Восстановление в промежуточное хранилище, независимая копия текущей базы до замены, блокировка автосохранения и синка на время переключения. Валидный старый импорт пока заменяет таблицы прежним способом; не считать его безопасным механизмом восстановления.
- Выгрузка несохранённого состояния при отказе записи и проверки интерфейса/перезагрузки на изолированной базе браузера.
- Проверки многовкладочной работы и операций создания/удаления страниц во время редактирования. Облачный протокол, outbox и конфликты этим пакетом не изменены.

Для получения локальной копии нужно выполнять инструмент этапа 0 в Firefox на ноутбуке, в том профиле и на том origin, где находятся рабочие заметки. Turso-копия не включает локальные изменения, которые ещё не были отправлены в облако. Отсутствие ноутбука не блокирует подготовку и изолированную проверку кода.
