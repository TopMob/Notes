## Цель и границы

Сохранить существующие заметки, сделать локальное сохранение устойчивым к ошибкам, затем обеспечить предсказуемую синхронизацию между устройствами. После стабилизации синка — укрепить ввод и оптимизировать приложение.

Первичный аудит включал чтение кода, сборку, тесты и изолированное воспроизведение ошибок. Он не устанавливает состояние production-данных, реальные права облачных токенов или поведение всех устройств. Пункты с условной применимостью сначала подтверждаем в отдельной среде.

Локальная БД — основное рабочее хранилище. Успех сохранения означает завершённую локальную транзакцию, а не успешный облачный запрос. Это не правило «любой локальный снимок всегда выигрывает»: чистая локальная копия должна принимать новые удалённые изменения, а при конкурирующих правках обе версии должны сохраняться.

## Конфликты без наложения и бесконтрольного роста

Это требования будущего протокола, а не уже внедрённое поведение.

- Рабочая страница одна. Конфликтная версия хранится отдельно и не добавляет второй набор штрихов/текста на тот же холст.
- Один и тот же конфликт определяется по ID сущности, базовой ревизии и hash конкурирующих версий; повторный ответ не создаёт ещё одну копию.
- У каждой отправки устойчивый ID операции. Таймаут и повтор используют тот же ID; старое подтверждение не закрывает более новую операцию.
- Бинарные assets и неизменённое содержимое по возможности хранятся один раз, версии ссылаются на них по ID/hash. Конфликт одного объекта не дублирует весь блокнот.
- Ограничить число параллельных операций, повторы, рост outbox и объём конфликтных копий. При достижении лимита сохранять локальную работу и показывать приостановку облачной операции; нельзя молча уничтожать неразрешённую версию.
- Автоматически очищать только разрешённые/явно отброшенные версии по установленному сроку хранения, после проверки ссылок. Не обещать нулевые накладные расходы: разные версии действительно требуют дополнительного места, но обычная работа не должна постоянно удваивать БД.

## Правила выполнения

- Никаких автоматических очисток пользовательской БД и массового переименования существующих ID.
- До изменения схемы или поведения PULL подготовить полную копию исходных данных и проверить восстановление в отдельном хранилище.
- Маленькие изменения в отдельных ветках/PR; каждый PR содержит связанный дефект, воспроизведение и проверку результата.
- Версии схемы расширять аддитивно. Старые бэкапы и бандлы сохранять читаемыми; не выдавать отсутствующие старые поля за доказанную пустоту или удаление.
- Нельзя выпускать переходную комбинацию новых снимков и старого PULL, которая теряет данные. Если связанное исправление нельзя разделить безопасно, оно выпускается одним проверенным изменением.
- Ошибки, конфликты и неполные ответы должны быть видимы; их нельзя превращать в статус «сохранено/синхронизировано».
- Проверки production выполняются сначала только на чтение. Запись и развёртывание — после подготовки конкретного изменения и согласования выпуска.
- Нельзя обещать абсолютную сохранность при очистке браузера, потере устройства или аварийном закрытии до завершения локальной записи. Для этих случаев нужны независимые копии и честный статус.

## Минимальная матрица приёмки синка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Новые локальные данные + старый ответ облака | Локальные правки остаются |
| Чистая локальная копия + новые удалённые данные | Принимается новая подтверждённая версия |
| Одновременные правки одной страницы на двух устройствах | Сохранены обе версии; конфликт доступен для решения |
| Удаление последнего элемента/всей страницы | Не появляется повторно на другом устройстве |
| Удаление и восстановление офлайн, затем рестарт | Операции сохраняются и согласованно применяются |
| Запись произошла, ответ сети потерян | Повтор не создаёт дубль и не откатывает новую версию |
| Новые правки во время PUSH/PULL | Подтверждение старой версии не стирает новые правки |
| Два запуска синка/две вкладки | Поздний ответ не откатывает состояние |
| Смена аккаунта/провайдера во время запроса | Данные и ответ остаются в своей области |
| Ошибка IndexedDB/записи изображения | Нет ложного успеха, очередь и состояние доступны |
| Неполный ответ/повреждённый бандл | Нет очистки, последняя исправная версия сохранена |
| Старая схема/старые ID/старые aliases | Данные и ссылки остаются читаемыми |
| Полный backup → чистый restore | Совпадают записи, изображения, ссылки и корзина |
| Старый клиент возвращается после обновления | Не обходит новую проверку версий |
