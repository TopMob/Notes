## Проверка качества

- Node-тесты исполняют реальные TS-модули. Подменяются границы платформы и IO.
- Полный набор: 132 проходящих теста; production-сборка проходит.
- Геометрия чернил сравнивается с прежними настройками perfect-freehand; проверяется инвалидирование кэша.
- Индекс сравнивается с полным перебором после перемещений, удалений и смены снимков, включая огромные границы.
- Проверяются отмена кадров, отсутствие dirty-изменений при no-op и освобождение изображений, в том числе при завершении загрузки после размонтирования.
- Отдельно проверено, что undo перемещения сохраняет более поздний текст как другого, так и самого перемещённого блока, включая сохраняемые diff.
- Chromium в новом профиле с синтетическими заметками: каретка и DOM после смены камеры, drag/resize на масштабе 150%, перо, перемещение выделения, ластик, undo/redo и переход страницы с зажатым пером.
- Пиксели слоя сравниваются с полной перерисовкой после добавления пера/маркера, перемещения и undo/redo.
- В экспортированном PNG проверяются пиксели текста и красного исходного изображения. Большая страница проверяется как ZIP; unit-тест сверяет байты и CRC файлов архива.
- Этот браузерный сценарий проходит также при CPU throttling 6×. Это проверка поведения при замедлении, а не обещание 60 FPS на конкретном ноутбуке.
- Имеющийся браузерный набор local-safety проходит: реальная IndexedDB, сохранение после перезагрузки, ошибки записи, две вкладки, очереди и поздняя гидратация изображения.

Персональные заметки и production-сайт для проверок не открывались. В браузерных тестах все внешние запросы блокируются.

## Воспроизводимый замер

`npm run benchmark:canvas` сравнивает реальные модули с исходным коммитом `fce7292`; медиана 9 прогонов после прогрева. Canvas-команды подменены счётчиком, GPU и React в этот замер не входят.

| Сценарий | До | После |
| --- | ---: | ---: |
| Повторное рисование 500 готовых штрихов по 200 точек | 25,816 мс | 3,730 мс |
| Обновление индекса при перемещении одного из 10 000 объектов | 3,475 мс | 0,002 мс |

Во второй строке исключены затраты store, обходов массивов и рисования. Значения зависят от частот CPU и нагрузки; они характеризуют отдельные участки, а не ускорение всего сайта.

## Границы изменений

Все текстовые DOM-узлы остаются смонтированными. Общий transform устраняет работу с каждым блоком при движении камеры. Автоматическое размонтирование и обрезание содержимого за экраном не включались: таблицы могут выходить за ширину блока, а активный contentEditable должен сохранять выделение, каретку и историю ввода. Это сознательное ограничение ради качества, а не заявленная виртуализация.

Активный штрих использует прежний полный расчёт сглаживания на визуальный кадр; данные точек не отбрасываются ради скорости. Математика сглаживания, разрешение рабочего Canvas и глубина undo не снижались.

Для PNG один Canvas ограничен 16 777 216 пикселями (64 МиБ RGBA без учёта внутренних буферов браузера). Большой экспорт последовательно создаёт части по 2048 мировых единиц с масштабом 2×. В памяти остаются сжатые PNG и исходные данные; лимит Canvas не является лимитом всей памяти процесса. Экспорт свыше 1024 частей или лимита ZIP32 сообщает об ошибке до создания некорректного архива.

Для очень длинных страниц выходным форматом становится ZIP. Оригиналы изображений и заметки при экспорте не перезаписываются. Фактическое энергопотребление на ноутбуке и задержку пера на физическом стилусе следует оценивать на устройстве: CPU throttling не моделирует все особенности режима батареи.

## Повторный запуск

```powershell
npm test
npm run build
npm run benchmark:canvas
# NOTES_PLAYWRIGHT_MODULE — абсолютный путь к установленному модулю playwright.
$env:NOTES_CPU_THROTTLE = '6'
npm run test:canvas:browser
```

Production-сборка проходит; предупреждения Vite о крупном основном bundle и совместном статическом/динамическом импорте storage остаются. Новый PNG/ZIP helper загружается отдельным небольшим chunk при экспорте.
