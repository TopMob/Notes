# Завершение пакета исправлений синка

## SHA-256 по страницам: получение только изменившегося содержимого

Turso сохраняет SHA-256 страницы в служебной таблице `notes_page_revisions_v1` в той же транзакции, что и условная запись содержимого. При следующем изменении страницы старый хеш инвалидируется триггерами метаданных и элементов; штатный commit сразу записывает итоговую ревизию, а изменения старых/прямых клиентов пересчитываются при первом обращении. Неизменившиеся холсты для пересчёта хеша не читаются. Для существующих страниц без кэша выполняется однократное заполнение. Таблица и триггеры создаются сервером автоматически, исходные данные заметок не пересоздаются.

При PULL клиент отправляет `{id, revision}` для локально подтверждённых страниц текущего аккаунта. Сервер получает метаданные, кэш ревизий и нужное содержимое в одной транзакции; при совпадении SHA-256 возвращает метаданные и явное подтверждение `omittedPages`, без штрихов, фигур и текста этой страницы. Отличающиеся страницы, новые записи, удаления и содержимое без метаданных передаются прежним проверяемым способом. Большие ответы по-прежнему разбиваются на части. На клиенте SHA-256 неизменившихся страниц повторно не вычисляется, их локальное содержимое сохраняется. Короткая общая отметка аккаунта остаётся более дешёвой проверкой для повторного синка вообще без изменений.

Страница с очередью, незавершённым вводом, конфликтом, неизвестной ревизией или другим поколением локальных данных не отправляется как подтверждённая. Импорт бэкапа, смена провайдера и правки в локальном режиме инвалидируют такие подтверждения; облачная отправка в локальном режиме не создаётся. Перед локальным применением повторно проверяются снимок данных, очередь и поколение, включая изменения другой вкладки. SHA-кэш не заменяет проверку базовой версии при записи. Supabase пока сохраняет прежний путь.

Регрессионная проверка последовательных входящих изменений также исправила обновление карты локальных элементов внутри `safePull`: после записи нового элемента он теперь участвует в подтверждении итоговой базовой ревизии. Следующее изменение, в том числе удаление последнего штриха, не создаёт ложный конфликт из-за старой базы.

## Оптимизация повторных проверок 16 октября

Turso хранит короткую отметку изменений аккаунта в `notes_sync_clock`. Триггеры таблиц метаданных и содержимого обновляют её в той же транзакции, включая удаления, изменения без роста количества объектов и записи старых клиентов. Проверка отметки не читает холсты. Полный снимок получает свою отметку в одной read-транзакции с заметками. Ответ условной записи содержит предыдущую и новую отметки: клиент продлевает уже проверенную последовательность только при точном совпадении предыдущей отметки. Вмешательство другого устройства разрывает последовательность и требует полной проверки.

После успешной проверки повторный ручной синк в этой сессии может обойтись запросом отметки и локальных метаданных/очереди, без передачи всех штрихов. При перезагрузке или неизвестных изменениях облака проверяются ревизии страниц; страницы без актуального подтверждения загружаются целиком. Восстановление бэкапа инвалидирует подтверждения также в других вкладках через локальный маркер поколения. Supabase пока использует прежний путь полной проверки.

Автоматическая отправка Turso читает только записи и содержимое страниц из очереди; посторонние блокноты для проверки исходной ревизии не загружаются. Синк больше не перечитывает снимок второй раз, если не добавлял отсутствующие облачные записи. Содержимое для сравнения группируется по страницам за один проход, а очередь индексируется набором ключей. Для неизвестных изменений другого устройства теперь используется описанное выше сравнение SHA-256 по страницам.

## Обновление 16 октября: большие снимки и переходы холста

Turso больше не требует уместить весь облачный снимок в ответ размером 3 МиБ. Новый клиент запрашивает `chunks-v1`: небольшие снимки приходят целиком, большие фиксируются в служебной таблице `notes_transfer_chunks` и читаются частями по 256 КиБ символов. Части принадлежат подписанному пользователю, имеют единый ID и SHA-256; браузер проверяет комплектность и контрольную сумму до распаковки и применения. Изменения заметок во время передачи не меняют уже сформированный снимок. Большие исходящие страницы также собираются из проверенных частей, после чего проходят прежнюю атомарную проверку базовой ревизии. Успешные передачи удаляются, незавершённые становятся недоступны через 15 минут и очищаются при следующем обращении пользователя. Таблица создаётся сервером автоматически; существующие таблицы заметок не пересоздаются.

Остаются технические защитные пределы: до 256 частей на передачу, серверная распаковка операции до 64 МиБ, прежние ограничения изображений и квоты инфраструктуры. Поддержка частей требует обновить сервер и клиент вместе. Старый формат небольших запросов и ответов поддерживается.

Перед переходом холста завершается текущий жест на исходной странице. Незавершённое взаимодействие защищает страницу от входящей синхронизации ещё до отпускания пера. При смене страницы временные холсты и обработчик жестов создаются заново; вставка объектов с чужим `pageId` блокируется. Создание страницы переключает активный заголовок после успешной загрузки холста. Фоновая синхронизация других страниц не перезагружает открытый холст, а запоздалое обновление списка не возвращает пользователя на прежнюю страницу.

9 октября 2026. Продолжение `DURABLE_SYNC_PROGRESS.md`. Выпуск в `main` разрешён пользователем. Полный бэкап рабочих браузерных данных остаётся отложенным; тесты выполнялись в отдельных хранилищах.

## Реализовано

- Общее основание версии — SHA-256 нормализованных метаданных и полного содержимого страницы. Оно записывается локально после подтверждённой отправки или принятого согласованного PULL. Очередь захватывает базовую ревизию при локальной записи. Служебные отметки хранятся в существующей таблице IndexedDB 3; дополнительного обновления схемы и копии каждого холста нет.
- Turso работает через `/api/sync` на Vercel. Сервер проверяет подпись Clerk JWT, issuer, срок действия, nbf и допустимый azp; пользователя берёт из подписанного sub. Клиент не передаёт SQL и не выбирает владельца запроса. Проверка базовой версии, метаданные и бандл страницы выполняются в одной write-транзакции SQLite. Занятый чужим пользователем ID отклоняется.
- В Vite установлен явный список публичных префиксов env. Turso credentials исключены, в том числе из полного `import.meta.env`. Сервер использует `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` с временной совместимостью с прежними `VITE_TURSO_*` переменными Vercel. Браузер к Turso напрямую больше не обращается.
- Supabase получает согласованный снимок через SQL-функцию `notes_pull_v1`. `notes_commit_v1` блокирует объект, сравнивает исходные строки метаданных/элементов и атомарно записывает страницу и бандл. Пакет SQL закрывает прямые записи старых клиентов и устанавливает политики чтения по Clerk sub. Без установленного пакета новые запросы Supabase показывают ошибку настройки; небезопасного отката на обычный upsert нет.
- Чистая локальная версия с известным основанием принимает изменения другого устройства, включая пустой холст, удаления и восстановление. Холст заменяется целиком в одной локальной транзакции. Корзина сохраняет содержимое; ID и локальные aliases сохраняются. Снимок локальных записей проверяется повторно внутри транзакции, чтобы не пропустить правку другой вкладки.
- Конкурирующие/неизвестные версии приостанавливаются и доступны в настройках облака. Пользователь выбирает рабочую версию. Для страницы второй вариант сохраняется отдельной страницей с устойчивым ID и получает собственную очередь; повторный выбор не создаёт ещё одну копию. Альтернативные метаданные блокнотов/разделов сохраняются отдельно; прежние названия видны в истории настроек.
- Поздний ответ подтверждает только свою операцию. Если в процессе записи появились новые локальные правки, их базовая ревизия продвигается к подтверждённой предыдущей версии в одной транзакции с подтверждением. Смена аккаунта/провайдера отменяет применение ответа.
- Удаления родителей больше не каскадируют в облаке без проверки дочерних ревизий: каждый затронутый объект имеет свою операцию. Расходящиеся дочерние версии остаются восстановимыми.
- Изображения передаются бинарно. Turso получает и отдаёт части до 512 КиБ, оригинал до 64 МиБ, с SHA-256; неполная/повреждённая сборка не считается изображением. ID не может быть заменён другими байтами. После полной проверки сохраняется маленький manifest; HEAD и подтверждение страницы проверяют его без повторного чтения всех байтов. Supabase использует закрытый bucket `notes-assets`, неизменяемые пути с hash и manifest по владельцу, до 50 МиБ. Перед подтверждением страницы проверяется готовность её изображений, при чтении сверяется checksum.
- Ссылки `blob:` для изображений с `data-asset-id` исключаются из облачного HTML. На другом устройстве object URL строится из загруженного Blob. Локальный оригинал не преобразуется. Для ранее созданных заметок доступные локальные оригиналы дозагружаются в облако.
- Исправлено обновление активной страницы/раздела: после PULL используются свежие метаданные из базы. Окно облака ограничено высотой экрана; список конфликтов прокручивается внутри окна.
- Совпадающий снимок подтверждает базовые ревизии без повторной записи метаданных/холста и перезагрузки редактора; пустая по изменениям синхронизация не сбрасывает undo.
- Изображение, пришедшее после текста, обновляет свой object URL событием готовности, без повторного открытия страницы и замены текста редактора.

## Необходимые действия в облачных панелях

Доступных авторизованных вкладок и CLI-сессий Vercel/Turso/Supabase в этой среде нет. Эти действия не выполнены и не считаются завершёнными проверками:

1. **Turso:** создать новый ключ, установить его в Vercel как `TURSO_AUTH_TOKEN` (URL — `TURSO_DATABASE_URL`), выполнить redeploy и проверить вход/синк с ноутбука. Затем отозвать прежний ключ. Старый ключ уже был опубликован в предыдущих JS-сборках; удаление из новой сборки не отзывает его и не отключает старый клиент. Не публиковать новый ключ в Git или сообщениях. После перевода удалить старые `VITE_TURSO_*` переменные.
2. **Supabase:** проверить типы существующих столбцов и выполнить `scripts/supabase-sync-v1.sql` в SQL Editor. Пакет рассчитан на `camera` и `background` JSON/JSONB и отказывается от неподходящих старых типов до изменения политик. Проверить вход Clerk и синк на тестовой странице; bucket закрытый. SQL не удаляет заметки, но намеренно отзывает прямые облачные записи старых клиентов. До установки можно продолжать пользоваться Turso и локальным сохранением.
3. **Приёмка на ноутбуке:** обновить/закрыть старые вкладки, проверить наличие рабочих заметок, локальное сохранение, перезапуск и перенос одной тестовой страницы/изображения. В этой среде нет действующей пользовательской Clerk-сессии, поэтому полный production-сценарий после входа не заявляется проверенным.

Серверная функция остаётся в существующем проекте Vercel; отдельный платный сервис не добавляется. Существующие лимиты платформ действуют: крупный JSON-пакет, неподдержанный MIME или исчерпание квоты оставляют локальные данные и очередь, но приостанавливают облачную отправку.

## Ограничения и откат

Отдельный полный backup/import, оптимизация, перо и текстовый редактор этим пакетом не переделаны. Старые браузерные данные без известной базовой ревизии не выдаются за согласованные автоматически: при отличии требуется явный выбор версии. Старые ссылки без `data-asset-id` не превращаются в восстановленные изображения; недоступный оригинал восстановить из одного blob URL нельзя.

В отсутствие отзыва старого ключа Turso старый или сторонний клиент всё ещё может записывать напрямую, обходя новый протокол. После отзыва и установки Supabase SQL штатные облачные записи идут через условные исполнители. Полноценная физическая изоляция локальной базы для разных аккаунтов остаётся отдельной задачей; текущий ограничитель владельца блокирует отправку чужого локального хранилища.

При регрессии остановить облачную отправку локальным режимом. Сохранить IndexedDB 3, таблицу очереди, серверный шлюз и запрет публикации Turso env. Нельзя просто вернуть старый JS с новым секретом или понизить IndexedDB до 2. Совместимый reader из `DURABLE_SYNC_PROGRESS.md` читает заметки и очередь; возврат старого отправителя не является безопасным откатом. Для интерфейсного отката сервер и фильтр секретов оставить, облако временно остановить. Новые таблицы assets не удалять: на них ссылаются заметки и конфликтные страницы.

Документация использованных механизмов: [транзакции libSQL](https://tursodatabase.github.io/libsql-client-ts/interfaces/Transaction.html), [проверка Clerk JWT](https://clerk.com/docs/guides/sessions/manual-jwt-verification), [Node-функции Vercel](https://vercel.com/docs/functions/runtimes/node-js), [лимит файлов Supabase](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/storage/uploads/file-limits.mdx).
