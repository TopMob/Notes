   - Реализована бинарная передача изображений в облако (chunked upload/download для Turso, private bucket `notes-assets` для Supabase) с вырезанием временных `blob:` URL из хранимого HTML.

## 4. Детальный разбор изменений по направлениям

### 4.1. Локальная безопасность и хранение (IndexedDB)
- **Схема базы данных:** Версия базы увеличена с `2` до `3` (`src/db/idb.ts`). Добавлен object store `syncOutbox` с составным первичным ключом (`['provider', 'userId', 'entity', 'entityId']`).
- **Транзакционность:** Локальное изменение сущности и запись в `syncOutbox` выполняются в единой транзакции IndexedDB (`persistEntity` в `storage.ts`). Это гарантирует, что если запись упала, операция отправки не появится; если запись прошла, намерение синхронизации зафиксировано надёжно.
- **Отказоустойчивость при QuotaExceededError:** При ошибке сохранения холста diff не удаляется, а объединяется обратно в очередь правок страницы (`restoreDirty`), а UI показывает внятную индикацию проблемы.

### 4.2. Архитектура синхронизации (Sync Protocol v1)
- **Протокол ревизий:** Вместо ненадежного сравнения клиентских таймстемпов (`updatedAt`), протокол использует канонический SHA-256 хеш (`protocol.mjs`). Хеш учитывает порядок, геометрические свойства, штрихи и метаданные.
- **Серверный шлюз Turso:**
  - Клиентский код `tursoProvider.ts` превращён в тонкий HTTP-клиент к `/api/sync`.
  - Серверная функция работает на Node.js среде Vercel (`api/sync.mjs`), выполняет авторизацию через `server/sync-auth.mjs` и проводит коммит в libSQL в рамках транзакции (`server/turso-sync.mjs`).
  - Успешный коммит возможен только если текущая облачная ревизия совпадает с `expected` ревизией клиента.
- **Supabase RPC:**
  - Написаны функции `notes_commit_v1` и `notes_pull_v1` (`scripts/supabase-sync-v1.sql`).
  - Прямые мутации от анонимных пользователей закрыты политиками безопасности (RLS).
- **Разрешение конфликтов:**
  - Модуль `src/services/sync/conflicts.ts` и `revisionState.ts` выявляет конфликтующие версии.
  - Если локальная и облачная страницы разошлись, обе версии сохраняются. В интерфейсе `CloudSettingsModal` появляется секция со списком конфликтов, позволяющая выбрать желаемую версию или сохранить копию страницы с суффиксом.

### 4.3. Синхронизация бинарных ресурсов (Assets)
- Ранее вставленные изображения существовали только локально. Теперь реализована сквозная передача:
  - Перед отправкой страницы вычисляются все `assetIds`.
  - Картинки загружаются в облако частями по 512 КБ с проверкой SHA-256 хеша.
  - При PULL страницы на другом клиенте недостающие ассеты скачиваются в локальную IndexedDB, после чего генерируется событие `ASSET_READY_EVENT`, динамически подставляющее живой `blob:` URL в `<img>` без перезагрузки текстового редактора.

## 5. Оставшиеся открытые вопросы и риски

### 5.1. Критичность: Средняя (Функциональность и запуск)
1. **Startup Crash при отсутствии Clerk ключа (A16):**
   - **Где:** `src/main.tsx`, `src/components/auth/AuthControls.tsx` и `src/components/modals/CloudSettingsModal.tsx`.
   - **Суть:** Если в `.env` отсутствует `VITE_CLERK_PUBLISHABLE_KEY`, `main.tsx` рендерит `<App />` без `<ClerkProvider>`. При этом `<Header />` монтирует `<AuthControls />`, где вызов `useUser()` немедленно бросает исключение:
     `Clerk: useUser can only be used within the <ClerkProvider /> component.`
   - **Решение:** Добавить проверку наличия ключа в `AuthControls` или обернуть хуки в защитный контекст (заглушку гостевого режима), чтобы приложение могло работать чисто локально без облачных переменных.

2. **Несанитизированный HTML при вставке формул и текста (A13):**
   - **Где:** `src/components/text/TextBlockView.tsx`.
   - **Суть:** Вставка текста со знаком степени (`^`) преобразует строку через `convertPowersToSuperscript` и выполняет `document.execCommand('insertHTML', false, converted)` без санитизации тегов. Также имя файла вставляется в `alt="${imageFile.name}"` без экранирования HTML сущностей.
   - **Решение:** Пропускать вставляемый HTML через парсер/санитизатор и экранировать атрибуты перед сборкой разметки.

### 5.2. Эксплуатационные задачи (Требуют действий пользователя в веб-панелях)
1. **Turso Secret Rotation:**
   - Прежний токен `VITE_TURSO_AUTH_TOKEN` был скомпрометирован публикацией в старых сборках.
   - **Действие:** Сгенерировать новый auth token в панели Turso, прописать в Vercel Environment Variables под именем `TURSO_AUTH_TOKEN` (без префикса `VITE_`), выполнить Redeploy, после чего удалить старый ключ в панели Turso.
2. **Supabase SQL Migration:**
   - **Действие:** Зайти в SQL Editor проекта Supabase и применить скрипт `scripts/supabase-sync-v1.sql`. Создать Storage Bucket `notes-assets` (private).

### 5.3. Ограничения локального бэкапа (A07)
- Экспорт в JSON (`exportFullBackup` в `storage.ts`) делает снимок текстовых данных и штрихов, но не сериализует бинарные картинки из таблицы `assets`. Пользователь, сделавший JSON бэкап и восстановивший его в чистом браузере, получит плейсхолдеры вместо картинок.
- **Решение:** Реализовать формат бэкапа v2 (например, ZIP-контейнер или JSON с base64/ассетами и манифестом).
